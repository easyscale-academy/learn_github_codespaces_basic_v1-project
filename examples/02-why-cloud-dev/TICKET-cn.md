# 读懂这门课的出发点

## 1. 目标

这是一篇纯阅读的开篇, 没有任何需要动手的操作. 它的作用是让你在开始装东西, 点按钮之前, 先明白自己为什么要学这些. 读完之后, 你应该能判断这门课是不是写给你的, 也能说清楚云端开发环境到底在替你解决什么麻烦. 这个判断很重要, 因为知道自己为什么学的人, 遇到卡壳时更容易撑过去.

---

## 2. 要做的事情

1. 完整读一遍这一篇的 README.
2. 读完后想清楚自己属于哪种情况: 如果手上只有 Windows 电脑, 明确知道接下来要学的东西是在替你解决什么; 如果已经有 Mac, 明确知道主力配置该怎么搭, 以及云端环境在你的日常里还占着哪两个位置.
3. 用自己的话把下面三件事讲一遍, 讲给同学, 导师, 或者就讲给自己听: 为什么科技行业在系统选择上如此一边倒; Mac 和 Linux 的血缘关系为什么会影响你装软件的顺利程度; 云端环境除了顶替 Mac, 对已经有 Mac 的人还有什么价值.
4. 如果你打算跟着这门课往下走, 确认自己已经有一个 GitHub 账号, 没有就先去 github.com 注册一个免费账号.

**预计用时:** 10 到 15 分钟

---

## 3. 检查清单

- [ ] **读完了开篇**: 完整读过一遍, 不是扫标题.
- [ ] **想清楚自己的处境**: 知道自己属于有 Mac 还是没有 Mac 的那一类, 以及主力环境该怎么安排.
- [ ] **说得清生态这件事**: 能解释为什么工具先在哪个系统上被造出来, 会决定你用起来顺不顺.
- [ ] **说得清血缘和一致性**: 知道 macOS 和 Linux 同属 Unix 一支, 也知道服务器几乎都是 Linux, 以及这两点分别意味着什么.
- [ ] **说得清云端环境对有 Mac 的人的价值**: 一是做一次性实验不弄脏主力机器, 二是 Codespaces 就是 VS Code, 学它等于顺便学会了本地要用的编辑器.
- [ ] **准备好账号**: 手上有一个可以登录的 GitHub 账号, 随时可以开始下一篇.
