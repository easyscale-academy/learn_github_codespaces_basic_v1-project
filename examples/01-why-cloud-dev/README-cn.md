# 为什么这门课从云端开发环境讲起

## 1. 概览

先把话说在前面: 如果你手上有一台 Mac, 这门课对你来说是可选的.

有 Mac 的话, 最舒服的那套组合早就摆在那里了, 系统自带的 Terminal 加上 VS Code 或者 PyCharm, 再配一个 GitHub Desktop, 装完就能干活, 体验比在浏览器里点一个云端环境好得多. 这篇不打算说服你放弃它.

这门课是写给另一批人的: 手上只有一台 Windows 电脑, 短期内也不打算换. 你会在学编程的路上反复撞到一些莫名其妙的墙, 而那些墙别人根本不会遇到. 这篇要讲清楚那些墙是从哪来的, 以及云端开发环境为什么正好是绕过去的办法.

---

## 2. 学习目标

一个刚开始学编程的人, 最容易被消耗掉的不是脑力, 是耐心. 教程第一步写着安装某个工具, 你照做, 然后卡住; 上网搜报错, 十个帖子给出十种说法, 挨个试; 一周过去, 你还没写出第一行真正属于自己的代码.

这里有一件很少有人明说的事: 同一份教程, 换一台电脑, 卡住的概率是完全不同的. 这不是玄学, 背后有很具体的原因. 搞清楚原因, 你就知道该怎么给自己选一条阻力最小的路, 而不是把力气花在和环境搏斗上.

读完这篇, 你将能够:

1. 说清楚为什么开发者群体在操作系统上的选择如此一边倒
2. 解释 Mac 和 Linux 的血缘关系, 以及它为什么直接影响你装软件的顺利程度
3. 判断本地环境和服务器环境不一致会给你带来什么额外成本
4. 说明云端开发环境解决的是什么问题, 以及它在你有了趁手的本地环境之后还剩下什么用途

## 5. 先说结论: 最舒服的那套配置长什么样

如果预算允许, 一个学编程的人最省心的起点是这样的: 一台 Mac, 用系统自带的 Terminal 敲命令, 用 VS Code 或者 PyCharm 写代码, 用 GitHub Desktop 管理版本. 四样东西, 装好就能用, 中间几乎不会有意外.

我把这个结论放在最前面, 是因为接下来的篇幅都在解释这个结论从哪来. 如果你已经有 Mac, 读到这里其实就可以去装这几样东西了; 如果没有, 请继续往下读, 后面有你的答案.

## 6. 为什么大家都在用 Mac

这件事最直观的证据不是任何一篇评测, 是开发者们用脚投出来的票.

去硅谷的公司里看一眼, 正经写代码的人, 粗略估计九成用的是 Mac. 这不是一个统计数字, 是一种走进办公室就能看到的景象. 最有意思的例子是微软: Windows 就是他们家的产品, 但除了做 Windows 专属的东西, 相当一部分开发者日常用的也是 Mac. 反过来, 那些流程几十年不怎么变的地方, 比如政府机关, 大多还是 Windows.

再看具体领域. 做 Data, 做 AI, 或者做设计和音视频这些创意方向, 情况更极端: 这些领域里最好的, 最新的工具, 几乎都是先支持 Mac. 你想用一个刚发布的库或者刚出来的模型工具, 在 Mac 上大概率是照着文档跑一遍就好了, 在 Windows 上你可能得先等一阵, 或者自己想办法绕.

需要说明的是, 这里说的不是 Mac 这台机器本身有多神. 硬件谁强谁弱是另一个话题. 真正起作用的是生态: 工具作者先在什么系统上开发和测试, 文档先照着什么系统写, 出了问题网上先有谁的解决方案. 生态一旦形成, 它就会自我加强.

---

## 7. 血缘: 为什么 Mac 上装东西省事

上面那个现象背后有一个技术上的原因, 值得单独讲清楚, 因为它能解释你遇到的大部分安装问题.

macOS 和 Linux 是近亲, 它们都属于 Unix 这一支, 命令, 目录结构, 权限模型, 大体上是一套东西. 而 Windows 走的是完全不同的另一条路.

这为什么要紧? 因为开发者工具这个世界, 绝大部分是在 Linux 上被造出来的, 尤其是那些有创新的, 走在前面的东西. 作者在 Linux 上写它, 在 Linux 上测它, 文档照着 Linux 的习惯写. 等这个工具传到你手上, 你如果用的是 Mac, 那基本是同一套语言, 文档上的命令复制粘贴就能跑; 你如果用的是 Windows, 中间就多了一层翻译, 而翻译总是会漏东西.

漏掉的部分, 就变成了你搜了半天也没人给出确切答案的那些报错.

---

## 8. 一致性: 你的电脑和服务器像不像

还有一条理由, 比上面那条更实际, 但初学者往往要等到吃了亏才意识到.

你写的代码, 最终大概率是跑在服务器上的, 而服务器几乎清一色是 Linux. 也就是说, 你的开发环境和真正的运行环境, 长得越像越好.

Mac 和服务器是近亲, Windows 和服务器是两个物种. 这个差别的代价不会一次性向你收取, 它是分期付款的: 本地跑得好好的东西传上去就报错, 路径分隔符不一样, 换行符不一样, 某个依赖在你这里装得上在服务器上装不上. 每一次都不致命, 但每一次都要花时间, 而且花掉的时间对你的技能毫无贡献.

说到底, 这等于你要为同一个项目维护两套方案, 一套让它在自己电脑上跑起来, 一套让它在服务器上跑起来. 这属于没事给自己找事.

---

## 9. 那么一台 Mac 要多少钱

既然结论是 Mac 更省事, 那绕不开一个问题: 这笔钱值不值得花.

对学习和日常工作来说, 你不需要顶配. 只要不是跑一个 T 的数据, 或者并行训练大模型这种重度负载, 一台基础款的 MacBook Air 就够了. 写到这篇的时候, 13 寸 M5 MacBook Air 的基础款是 16GB 内存加 512GB 存储, 售价 1099 美元. 苹果的价格和型号每年都在变, 你真要买的时候还是去官网确认一下, 但量级大致就是一千出头.

要不要花这笔钱是你自己的判断. 我想说的只是: 把它和你将来会花在环境问题上的时间放在一起算, 这笔账往往比看上去划算.

---

## 10. 没有 Mac 的人怎么办

好, 现在回到这门课真正要回答的问题. 你看完上面这些, 结论很清楚, 但你手上就是一台 Windows 电脑, 短期内也不会换. 难道就只能忍着?

不用. 这就是云端开发环境存在的意义.

思路其实很直接: 既然问题出在你本地这台机器上, 那就别在本地干活. 云端开发环境是跑在远程服务器上的一整套开发环境, 你通过浏览器访问它. 而那台远程服务器跑的是 Linux, 所以前面说的所有麻烦, 在那一侧根本不存在: 文档上的命令能直接跑, 工具能正常装上, 而且它和你代码最终要去的生产环境本来就是同一类系统.

换句话说, 你借了一台 Linux 机器来干活, 而你的 Windows 电脑只负责显示画面. 这门课用的 GitHub Codespaces 就是这样一个服务, 打开浏览器就能用, 个人账户还有一份不小的免费额度.

代价当然是有的: 需要联网, 免费额度有上限, 响应速度也比不上本地. 但和一周装不上一个工具比起来, 这些代价很好接受.

---

## 11. 云端环境的第二个用途

还有一点值得单独说, 因为它不会随着你换电脑而消失.

就算哪天你真的用上了 Mac, 云端环境依然有一个不可替代的用途: 做那些你不太确定的实验.

想试一个没听说过的工具, 想跑一段来路不明的代码, 想把某个东西装上去看看会发生什么 —— 这些事在自己的主力电脑上做, 心里总是有点虚, 因为搞乱了不好收拾, 有些东西卸载都卸不干净. 在云端环境里做就完全不一样: 开一个, 随便折腾, 弄完直接删掉, 什么痕迹都不留.

这才是它最舒服的地方. 你不用一边实验一边分神保护自己的系统, 可以把注意力全部放在实验本身上. 这一点下一篇会带你亲手体验一遍.

## 13. 回顾

- 有 Mac 的话, 最省心的组合是 Terminal 加 VS Code 或 PyCharm 加 GitHub Desktop, 这门课对你是可选的.
- 开发者选择一边倒, 根本原因是生态: 工具先在哪里被造出来, 文档就先照着哪里写.
- macOS 和 Linux 同属 Unix 一支, 而开发工具大多诞生于 Linux, 所以 Mac 上照着文档做通常就能成.
- 服务器几乎都是 Linux, 本地环境和它越像, 你要付的隐性成本越低.
- 没有 Mac 的解决办法是把开发环境搬到云端, 借一台 Linux 机器干活, 本地只负责显示.
- 即使将来有了趁手的本地环境, 云端仍然是做一次性实验的最佳场所.

---

## 14. 导师寄语

这一篇讲的其实不是操作系统之争, 而是一件更普遍的事: 遇到阻力时, 先看看阻力是不是选出来的.

初学者有个很常见的误解, 觉得卡住了就是自己不够聪明, 于是硬扛. 但很多时候卡住和聪明没关系, 只是你所处的位置本来就更费劲. 教程作者用的是另一套环境, 网上的答案是另一套环境下得出的, 你在做的事情等于一边学新知识, 一边给自己做实时翻译. 会慢是正常的.

真正有用的动作, 是把这种系统性的阻力识别出来, 然后想办法换个位置, 而不是在原地加倍努力. 云端开发环境就是这样一个换位置的办法, 成本低到几乎可以忽略, 收益却是整条学习路径的顺畅程度.

这个思路在别的地方也一样成立. 学一门乐器, 一把手感糟糕的琴会让你误以为是自己没天赋. 健身也是, 一个来回要一小时的健身房, 消耗掉的意志力比训练本身还多. 每次觉得某件事特别难坚持的时候, 值得先问一句: 是这件事本身难, 还是我把自己放在了一个更难的位置上?

先换位置, 再谈努力. 这个顺序反过来, 会白费很多力气.
