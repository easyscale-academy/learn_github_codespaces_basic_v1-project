# 把整条工作流讲一遍

## 1. 目标

这是一篇纯阅读的收尾, 没有需要动手的操作. 它的作用是把前面几篇学到的东西重新组织成一条你能完整复述的主线. 这一步值得认真做: 分开学会的操作和串起来能用的流程是两回事, 而只有后者才在真实场景里派得上用场.

---

## 2. 要做的事情

1. 完整读一遍这一篇的 README.
2. 合上教程, 凭记忆把一次完整的日常开发循环从头到尾讲一遍, 从打开 Codespace 一直讲到 Stop 或 Delete. 讲给同学, 导师, 或者就讲给自己听.
3. 讲完之后回去对照 README 里的那份清单, 看看漏了哪几步. 漏掉的地方通常就是你还不熟的地方, 值得回到对应的那一篇再看一眼.
4. 对照 README 里那份环境选择指南, 想清楚你自己接下来最常遇到的那类任务应该在哪做: 本地编辑器, Codespaces, 还是本地的 AI 桌面应用.
5. 读一遍最后那两个进阶方向, 挑一个你更想先了解的, 把它的搜索关键字或者那句话题存下来, 留着下次有空时用.
6. 找一个真实的小项目, 哪怕只是一个记笔记的仓库, 把这套流程完整用上一遍.

**预计用时:** 15 到 30 分钟

---

## 3. 检查清单

- [ ] **读完了收尾篇**: 完整读过一遍, 不是扫标题.
- [ ] **能复述整条主线**: 不看资料就能说出这门课的三段主线, 以及每一段解决的是什么问题.
- [ ] **能复述日常循环**: 凭记忆讲出一次完整的开发循环, 顺序基本正确, 没有漏掉确认分支和收尾清理这两头.
- [ ] **补齐了讲不出来的部分**: 对照清单找出自己卡壳的步骤, 并回到对应的 mini task 重新看过.
- [ ] **明白云端环境的定位**: 说得清它什么时候是最优解, 什么时候该换成本地环境, 以及哪个用途会一直保留.
- [ ] **会选环境**: 面对一个具体任务, 能根据手上的机器和活儿的性质说出该用本地还是 Codespaces, 以及理由.
- [ ] **挑好了下一步**: 能说出两个进阶方向分别在解决什么, 并且已经挑好先看哪一个, 关键字或话题句也存下来了.
