# 把六个分支操作各做一遍

## 1. 目标

先读完关于分支日常操作的教程, 然后在自己的仓库里把六件事逐个做一遍: 确认自己在哪个分支, 切换分支, 基于指定的分支创建新分支, 处理切换时遇到的未提交改动, 在本地把一个分支合并进另一个, 读懂状态栏上的同步指示器. 这样做的意义在于, 这六件事你以后每天都会用到, 而它们卡住人的地方通常不是操作复杂, 是不知道自己当前处在什么状态, 亲手做过一遍之后这种不确定感会消失大半.

---

## 2. 要做的事情

1. 完整读一遍教程, 特别是关于切换分支时未提交改动的那一节.
2. 打开一个属于你自己的仓库, 启动 Codespace. 确认左下角状态栏显示的是 `main`, 再看一眼终端提示符括号里的分支名, 确认两处一致.
3. 点击状态栏的分支名, 选择 Create new branch from..., 基于 `main` 创建一个叫 `branch-practice` 的分支. 留意创建完成后左下角的分支名变了.
4. 修改 `README.md` 并保存, 但先不要 commit. 注意分支名后面出现了星号, 这就是有未提交改动的信号.
5. 试着切回 `main`. 如果直接切过去了, 说明这个改动和 `main` 不冲突; 如果弹出了 `Your local changes would be overwritten by checkout.` 对话框, 选择 Migrate Changes, 然后确认改动跟着过来了.
6. 把改动 stage, commit, 再 push 上去. 留意状态栏的 `↑` 计数从 1 变回 0.
7. 切回 `branch-practice`, 打开源代码管理面板右上角的 `...`, 依次进入 Branch 和 Merge, 选择 `main`, 把刚才那个提交合并进当前分支.
8. 记下你这个仓库的地址, 格式类似 `https://github.com/your-username/your-repo-name`, 用于后续验收展示.

如果第 5 步没有弹出对话框, 不用觉得哪里做错了, 这恰恰说明改动不冲突, Git 直接把它带过去了, 这是最常见的情况; 想亲眼看看那个对话框, 可以在两个分支上分别修改同一个文件的同一行, 再尝试切换. 另外注意, 不要在那个对话框里点 Force Checkout, 它会直接丢弃你的改动且无法找回.

**预计用时:** 15 到 20 分钟

---

## 3. 检查清单

- [ ] **能随时确认当前分支**: 知道左下角状态栏和终端提示符这两个地方都会显示分支名, 也知道分支名后的星号代表什么.
- [ ] **会切换和创建分支**: 能通过状态栏的分支菜单切换分支, 并用 Create new branch from... 明确指定基础分支创建新分支.
- [ ] **说得清基础分支选错的后果**: 能用自己的话解释为什么推荐带 from 的那个选项, 以及基于错误的分支开工会在 PR 里表现成什么样.
- [ ] **会处理未提交的改动**: 知道大多数时候可以直接切换, 也能说清 Stash & Checkout, Migrate Changes, Force Checkout 三个选项分别会对改动做什么.
- [ ] **完成过一次本地合并**: 独立走完了一次 merge, 并能说清合并的方向是选中的分支进入当前分支.
- [ ] **读得懂同步指示器**: 能说出 `↑` 和 `↓` 分别代表什么, 以及 Sync 相当于哪两个操作的组合.
