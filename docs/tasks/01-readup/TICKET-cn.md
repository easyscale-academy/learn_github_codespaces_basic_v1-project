# 完成 GitHub Codespaces 入门全部课程

## 1. 目标

这门课要给你的不是一堆孤立的操作, 而是一条能从头走到尾的工作流. 读完全部 mini task 之后, 你应该能在浏览器里独立开出一个开发环境, 在里面改代码并让改动安全地留在 GitHub 上, 需要和别人协作时走分支加 Pull Request, 遇到分支状态不明时知道该看哪里, 并且对这件事花多少钱心里有数. 判断自己是否真的学会了, 标准很简单: 关掉教程, 能不能把这一整圈自己走一遍.

---

## 2. 要做的事情

1. 先读根目录的 README, 明白这门课怎么读.
2. 读 examples 的系列索引, 对整门课有张地图, 知道 8 篇分成哪三块.
3. 按编号顺序读完 examples 下全部 8 个 mini task, 每篇先读 README 再照它自己的 TICKET 逐项做完并确认.
4. 中间几篇需要你打开自己真实的 GitHub 账号动手做, 建议边读边做, 不要先读完再回头补.
5. 读完最后一篇梳理与拔高的内容, 想清楚自己学到了什么, 以及以后新任务该在本地做还是在云端做.
6. 最后合上教程, 找一个自己的小仓库, 从开 Codespace 到 PR 合并再到清理, 完整走一遍.

**预计用时:** 2 到 3 小时

---

## 3. 检查清单

- [ ] **全部 mini task 完成**: examples 下每个 task 的 TICKET 检查清单都已逐项打勾.
- [ ] **动手部分真的做过**: 需要在真实 GitHub 账号里操作的几篇, 都亲手做过, 不是只读过.
- [ ] **能独立复现**: 不看教程, 能把从开 Codespace 到 PR 合并再到清理的完整循环从头独立走一遍.
- [ ] **能讲清概念**: 能用自己的话解释 commit 与 push 的区别, 分支为什么有用, 以及 Stop 与 Delete 各自意味着什么.
- [ ] **有可查验的成果**: 手上至少有一个已合并的 Pull Request 链接, 能直接打开验证.
- [ ] **成本心里有数**: 知道自己的免费额度折合多少小时, 也知道去哪里查用量和设预算上限.

---

## 4. 关键能力

- 说清云端开发环境解决的是什么问题, 以及什么时候该用本地, 什么时候该上云端.
- 独立启动, 停止, 重启和删除一个 Codespace, 并说清 Stop 与 Delete 对数据和额度分别意味着什么.
- 在 Codespaces 界面里快速找到 File Explorer, Editor, Terminal 和源代码管理面板.
- 独立完成一次 Edit, Stage, Commit, Push 循环, 并确认改动真的出现在 GitHub 上.
- 解释 Stage 与 Commit 为什么被设计成两步, 以及 commit 与 push 的区别.
- 从 main 拉出分支, push 上去, 开 Pull Request 并合并回 main, 合并后完成清理.
- 随时确认自己在哪个分支, 有没有未提交的改动, 以及有多少 commit 还没推上去.
- 处理切分支时的未提交改动, 分得清 Stash and Checkout, Migrate Changes 与 Force Checkout 的后果.
- 算清免费额度按机器核数折算后的真实可用小时数, 并给 Codespaces 设一条带 Stop usage 的月度预算上限.
- 不看教程走完一次完整的日常循环: 确认分支, 开分支, 改, commit, push, PR, 合并, 清理.
