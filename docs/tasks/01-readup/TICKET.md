# Complete the Full GitHub Codespaces Getting Started Course

## 1. Goal

What this course gives you is not a pile of isolated operations, it is one workflow you can run end to end. After finishing every mini task you should be able to open a development environment in the browser, change code there and get those changes safely onto GitHub, use a branch and a Pull Request when you need to work alongside other people, know where to look when a branch's state is unclear, and have a clear idea of what all this costs. The test of whether you actually learned it is simple: close the tutorial and see if you can run the whole loop yourself.

---

## 2. What to Do

1. Read the root README first, so you know how this course is meant to be read.
2. Read the series index at 01 under examples, to get the map of how the rest of the content is grouped.
3. Read all 9 mini tasks under examples in numbered order, taking each one's README first and then working through its own TICKET item by item.
4. Do the hands on pieces in your own real GitHub account as you read, rather than reading everything first and coming back to them.
5. Read the closing piece, work out what you learned, decide whether your next task belongs locally or in the cloud, and pick one of the follow up directions to save the search terms for.
6. Close the tutorial, find a small repository of your own, and run the whole thing once, from opening a Codespace to merging a PR to cleaning up.

**Estimated time:** 2 to 3 hours

---

## 3. Checklist

- [ ] **Every mini task done**: the checklist in every task's TICKET under examples is fully ticked off.
- [ ] **The hands on parts actually done**: the pieces that need work in a real GitHub account were done by hand, not just read.
- [ ] **Can reproduce it alone**: without the tutorial, you can run the complete loop from opening a Codespace to merging a PR to cleaning up.
- [ ] **Can explain the concepts**: you can say in your own words what separates commit from push, why branches are useful, and what Stop and Delete each mean.
- [ ] **Has a verifiable result**: you have at least one merged Pull Request link that opens and checks out.
- [ ] **Clear on the cost**: you know how many hours your free allowance works out to, and where to check usage and set a budget cap.
- [ ] **Knows what comes next**: you can say what each of the two follow up directions from the closing piece addresses, and you have picked which one to look at first.

---

## 4. Key Capabilities

- Explain what problem a cloud development environment solves, and when to work locally versus in the cloud.
- Start, stop, restart, and delete a Codespace on your own, and say what Stop and Delete each mean for your data and your allowance.
- Find the File Explorer, Editor, Terminal, and source control panel quickly in the Codespaces interface.
- Run a complete Edit, Stage, Commit, Push cycle on your own, and confirm the change really landed on GitHub.
- Explain why Stage and Commit are two separate steps, and how commit differs from push.
- Branch off main, push it, open a Pull Request, merge back into main, and clean up afterward.
- Check at any moment which branch you are on, whether you have uncommitted changes, and how many commits are still unpushed.
- Handle uncommitted changes when switching branches, and tell apart what Stash and Checkout, Migrate Changes, and Force Checkout each do.
- Work out the real usable hours behind the free allowance once machine cores are factored in, and set Codespaces a monthly budget cap with Stop usage enabled.
- Run a full daily loop without the tutorial: check the branch, branch off, edit, commit, push, PR, merge, clean up.
