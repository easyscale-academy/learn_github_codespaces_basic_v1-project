# GitHub Codespaces Getting Started Overview

> In one line: this course teaches you to set up a development environment in the browser with GitHub Codespaces and run the core Git workflow inside it. For the full picture, see [README-ORIGINAL.md](README-ORIGINAL.md).

## 1. What This Course Is

Setting up a development environment is where beginners get stuck longest, especially when all they have is a Windows machine. GitHub Codespaces moves the whole environment into the cloud: open a browser and you have a configured Linux machine, with nothing installed locally. This course gets you actually using it, doing the things a developer does every day, without typing a single Git command.

This is a readup teaching repository: the repo is the course, and the content is split into numbered mini tasks under [examples/](examples/). You do not need to treat it as a book to read cover to cover. Just follow the reading path below, go through the mini tasks in order, and work through each one's TICKET as you read.

---

## 2. How to Read It

1. Go into [examples/](examples/) and read from 01 onward in numbered order. 01 is the series index, and it gives you the map: how the rest of the mini tasks are grouped and what each group solves.
2. In each directory, read the README first to see what that piece teaches, then work through its TICKET, doing every item under "what to do" and using the checklist to confirm you actually did it.
3. Finish one before starting the next, and do not skip around. The earlier pieces are the foundation for the later ones, and 05 through 07, the Git thread, builds up layer by layer.
4. Several pieces need you to work in your own real GitHub account. Do them as you read rather than reading everything first and coming back.
5. The last piece ties the whole workflow together, gives you a call on whether a new task belongs locally or in the cloud, and points at two directions to dig into next.
6. What counts as done: every mini task's TICKET checklist ticks off, and you can run a complete development cycle yourself without the tutorial open.

---

## 3. What You Can Do When You Finish

You can spin up a cloud development environment and keep its cost under control, run the full cycle inside it from editing code to commit and push to opening a branch, raising a Pull Request, and merging back into main, and you know where to look when a branch's state is unclear. More to the point, this workflow is not tied to Codespaces: moving to a local VS Code or GitHub Desktop costs you almost nothing. If you want to go further, the last piece gives you directions and search terms you can use directly.
